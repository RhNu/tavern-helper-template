# 测试

本仓库使用 Vitest 运行测试，当前只提供 Node.js 测试环境，不启用 coverage、DOM 模拟或真实浏览器测试。

## 测试分类

- 普通测试命名为 `*.test.ts`，与被测源码放在同一目录。
- 涉及构建流程、文件系统或产物契约的测试命名为 `*.integration.test.ts`。
- 可跨测试复用的输入样本放在对应领域的 `fixtures` 目录，不要在测试文件中复制大型样本。

Vitest 将普通测试归入 `unit` project。构建集成测试归入 `integration` project，串行执行并使用更长的超时时间，
避免测试同时操作构建缓存或输出目录。

## 运行命令

- `pnpm test`: 一次性运行全部测试，也是 CI 和 `pnpm check` 使用的命令。
- `pnpm test:watch`: 在本地监听文件并运行受影响的测试。
- `pnpm test:unit`: 只运行普通测试。
- `pnpm test:integration`: 只运行构建集成测试。

## 编写约定

- 从 `vitest` 显式导入 `test`、`expect`、`vi` 等 API，不使用全局测试 API。
- 每个测试应能独立运行，不依赖执行顺序或其他测试遗留的 mock、环境变量和全局变量。
- 优先测试纯逻辑和对外契约；时间、随机数、网络和宿主接口应使用可恢复的 mock 或依赖注入。
- 创建临时文件或修改进程状态的测试必须在 `finally` 或测试清理钩子中恢复现场。
- 不发起真实网络请求，不依赖开发机上已有的缓存、密钥或 SillyTavern 实例。

需要 DOM 或真实浏览器环境时，应先新增独立的 Vitest project 和明确的文件命名约定，不能把环境模拟加入所有测试。
